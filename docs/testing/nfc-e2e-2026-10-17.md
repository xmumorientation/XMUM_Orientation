## Reproduction and evidence

1. Temporarily assign Faci/Freshie demo accounts to clean Group 10.
2. Grant TF pieces 1–4 through Admin. GM opens `/guardian`, chooses TF / Group 10: 4/5, incomplete.
3. Grant TF piece 5. Re-select the group: 5/5 and `Confirm set and mark redeemed` appear.
4. GM submits with note `NFC E2E 2026-10-17 G10 TF — generated ordinary TF sticker`.
5. UI reports `Set redeemed for Track & Field. Hand over the NFC card now.`
6. Faci Group 10 inventory shows TF 5/5, Key ready. Open the newly generated ordinary TF NFC link.
7. Activation page reports `Not verified yet`; TF remains dormant.

Post-failure authenticated reads:

- `nfc_guardian_verifications`: Group 10 / TF verification ID 2 exists, unconsumed, created by the GM demo.
- `puzzle_redemptions`: no Group 10 row.
- `fn_puzzle_status(10, 'TF')`: 5 pieces, complete true, **redeemed false**, projector_activated false.
- Faci profile at failure: Group 10, role faci.
- TF projector: activated_by_group null, activated_at null.
- NFC token ID 23: ordinary TF token, unused, test_run_id null.

This establishes a live mismatch between the Guardian write path and the legacy redemption status / activation path. The checked-out `/activate` page invokes `fn_activate_projector`; migration 0081's implementation checks `puzzle_redemptions` for ordinary cards. The live function definition itself was not retrieved, so migration text is explanatory evidence, not proof of the deployed definition. The live table and response observations above are independently confirmed.

The Guardian page also sets its local `redeemed` state to true after a successful RPC without re-reading server status, allowing the UI success to hide this mismatch.
